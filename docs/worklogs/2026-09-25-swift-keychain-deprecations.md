## Problem

Installer builds emitted seven deprecated Security ACL API warnings from custom Keychain prompt wording, plus invalid linker search paths generated by the installed Swift 6.4 Command Line Tools.

## Implemented solution

Removed SecAccess/SecACL creation and modification. Credential CRUD continues through SecItemCopyMatching, SecItemAdd, SecItemUpdate and SecItemDelete with the same service/account identity, labels and migration policy. Updating an existing item no longer reads or rewrites its ACL. New items use the system default access policy. Settings briefly explains what Keychain stores; custom text inside the OS prompt is no longer promised. Removed the obsolete ACL-renaming test; credential migration/failure tests remain.

## Reasoning

[Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) distinguishes the supported SecItem API from the legacy SecKeychain/ACL APIs. Removing cosmetic ACL manipulation eliminates the deprecated calls without moving or deleting real credentials. The explanation now lives in app UI, following contextual [HIG Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy) guidance.

## Validation

Passed: make test-macos (60 tests, 18 suites) and make install-macos. Neither log contains deprecation warnings. Installer packaging and signature verification passed. No real Keychain reads/writes or consent prompts were exercised; no recording/upload. Settings text was compiled but not separately visually inspected.

## Technical debt and blocker

The file-based credential backend remains for compatibility with existing credentials and ad-hoc local signing. Future data-protection Keychain migration needs stable signing/entitlements and copy-before-delete migration tests; changing storage as part of cosmetic warning cleanup would introduce credential-loss risk.

Linker warnings remain for CommandLineTools/Developer/usr/lib and CommandLineTools/Developer/Library/Frameworks. The installed directories actually live below CommandLineTools/Library/Developer. SwiftPM's [PIFBuilder](https://github.com/swiftlang/swift-package-manager/blob/main/Sources/XCBuildSupport/PIFBuilder.swift) adds testing search paths, and the standalone swiftbuild backend resolves these against the wrong platform layout. Disabling test products and passing Xxcbuild build-setting overrides did not remove the paths; those experiments were not retained. Switching to the native build engine was rejected because this toolchain explicitly marks it deprecated. No warning suppression or system-directory symlinks added. Remediation: an upstream CLT/Swift build fix or validation with a stable full Xcode toolchain when available. No Xcode installation was present on this Mac.

This supersedes the earlier decision to retain deprecated ACL customization recorded in the list-insets worklog. The unrelated .vscode/settings.json user modification was preserved.
