## Problem

The repository needed a complete native macOS meeting interface that builds with Command Line Tools, supports the existing meeting workflows, and follows Apple's Human Interface Guidelines.

## Implemented solution

- Added the SwiftUI application scene, standard Settings scene, menu commands and shortcuts, menu bar recording controls, and graceful recording finalization on quit.
- Added a native three-column meeting library with search, recording, audio import, legacy library import, text export, and confirmed destructive actions.
- Added editable transcript/speakers, notes, summaries, to-dos, persistent meeting and person/tag chat, people/tag management, server library search/import, server archive, and resumable transcription actions.
- Added AVKit playback with default mixed playback of all simultaneous audio tracks, individual track selection, timestamp seeking, saved duration, and live recording elapsed time. Cancellation and generation checks prevent stale asynchronous playback preparation from updating a changed view.
- Added recording source and optional microphone voice-processing settings. Source/processing changes are disabled during recording; capture status appears above the content.
- Added `ViewState` as an alias of `SwiftUI.State` to select the native property wrapper when the installed CLT SDK exposes an unavailable SwiftUI macro implementation.

## Reasoning

Native `NavigationSplitView`, lists, forms, toolbar actions, system colors, semantic fonts, and AVKit playback preserve standard macOS keyboard and accessibility behavior. Relevant HIG URLs and principles are cited beside the implementation. The menu bar restores the named main window even after it closes. Playback is unavailable during active recording.

Apple's [voice-processing session](https://developer.apple.com/videos/play/wwdc2023/10235/) documents noise suppression, gain control, and ducking that affects other audio. The UI therefore exposes processing as an explicit option and explains route dependence and possible playback-volume changes; it does not promise removal of Teams/Zoom audio leaking into a microphone. The [ScreenCaptureKit microphone session](https://developer.apple.com/videos/play/wwdc2024/10088/) documents a separate microphone stream, without an echo-cancellation guarantee. Core retains the macOS 14.2-compatible microphone implementation. Capture status follows [HIG Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback), while primary recording commands remain in the toolbar.

## Technical debt

- **CLT `ViewState` alias:** accepted to support the installed SDK's missing macro plugin without requiring Xcode. Consequence: one additional wrapper name in UI source. Remediation: remove the alias and restore `@State` when the supported CLT versions provide the necessary plugin or no longer attach that macro.
- **Server search transcript import:** the server search endpoint exposes transcript text without original segment timing. Imported search results are represented as one segment; source audio and speaker timings cannot be reconstructed from that response. Remediation: use a future detailed server meeting/download endpoint to preserve structured segments and source artifacts.
- **Real-device audio validation:** deterministic tests and compilation cannot prove acoustic echo suppression, route transitions, microphone permissions, or speakerphone quality. Final real-device capture checks remain required; this is a validation gap, not a claimed successful acoustic test. Remediation: record and review microphone-only, system-only, combined speaker/headphone, and device-change sessions on supported macOS versions.
