**Problem:** The existing macOS client requires Rust and CMake and presents a browser UI. A native SwiftUI client should build using only Apple's Command Line Tools and also support Xcode.

**Implemented solution:** Added an independent Swift package in `apps/client-macos-swift`, with local storage and audio capture, SwiftUI meeting workflows, people/tags/contextual chat, server OAuth/transcription/search/verified archives, and compatible AI services. Root `make install-macos` builds, signs, stages, and opens a Finder installer. Added build/run/doctor/test targets and setup guides. Native views cite the applicable HIG principles in source. The user's follow-up prompted deeper audio research; agents integrated AVAudioEngine voice processing, timing, bounded writes, capture health, and conversion improvements, with evidence in `AUDIO_DESIGN.md`.

**Reasoning:** Apple frameworks and Swift Package Manager avoid third-party build prerequisites. Separate bundle and library identities prevent accidental interference with the existing Rust client. Native controls and contextual HIG citations document interface choices. Work split across recording/storage, interface, services, and packaging/integration agents at the user's request.

**Technical debt:** The native client has its own versioned JSON library and partial legacy importer instead of sharing the Rust storage engine; this avoids concurrent writers and permits independent installation, but means two implementations of domain behavior must remain compatible with the server. Future work should add fixture-based cross-client migration coverage and voice-embedding/history migration. Whole-library atomic writes simplify rollback but can become expensive with large transcripts; move to independently versioned per-meeting documents with bounded background persistence when scaling the library. `ViewState` aliases SwiftUI's existing property wrapper to avoid SDK 27's missing CLT macro plugin; the test script explicitly discovers the installed Swift Testing plugin to work around the same toolchain's test module-emission issue. Remove these compatibility measures once supported CLT releases no longer need them. Immutable archive checkpoints intentionally retain their first snapshot, so later local edits are not synchronized; a versioned server archive/update contract is the future remediation. Direct transcription uses hard ten-minute excerpt boundaries; evaluate overlap/deduplication with representative speech before changing recognition behavior. Full Rust parity is not claimed: concurrent sessions, configurable MP3/Opus capture, voice-embedding matching, local HTTP API, and Claude Code subprocess support remain in the Rust client.
